# RootGuard — حزمة تسليم هندسية لكلود | v1.0 | 22 أكتوبر 2026
اسم عمل قابل للتغيير. الهدف: تطبيق أندرويد للحماية بالروت، فايروول وتحليل سلوكي محلي، مصادر تهديدات، ويزارد وأوضاع تشغيل.

## طريقة التسليم
1. ارفع ملف ZIP كاملًا إلى كلود وفكّه داخل المشروع.
2. انسخ محتوى `CLAUDE_START_HERE.md` في المحادثة.
3. إذا كان لديك مشروع حالي، اطلب من كلود جرده ودمج التصميم فيه قبل إنشاء مشروع بديل.
4. اطلب أولًا شريحة تنفيذ فعلية: اكتشاف القدرات ← إعداد سياسة ← معاينة ← تطبيق على جهاز اختبار ← تحقق وتراجع.

## ماذا يوجد هنا؟
- مخطط هندسي وحدود الصلاحيات وخطة تنفيذ واختبارات وقواعد للخصوصية.
- ثلاثة مخططات SQL: الإعدادات والحماية، القياسات والسلوك، ومعلومات التهديدات.
- ثلاث قواعد SQLite فارغة منشأة من المخططات، وليست قواعد بيانات إنتاج مشفرة.
- عقود Kotlin مرجعية، عقود IPC بصيغة JSON Schema، أمثلة إعداد وتنبيهات.
- تنفيذ Python مرجعي صغير للإحصاء واختبارات للمخططات والتحليل؛ ليس محرك أندرويد.
- ملفات تحقق وفهرس وبصمات SHA-256.

## حالة التسليم
هذه بنية وتصميم وعقود ونواة إحصائية مرجعية؛ ليست تطبيقًا مكتملًا، ولا APK، ولا محرك فايروول مطبقًا. لم تُختبر على هاتف فعلي. Kotlin غير مترجم في هذه البيئة. نتائج التحقق المحلي موثقة في VALIDATION.md.

## قرارات أساسية
- الواجهة دون روت؛ مساعد امتيازات صغير ومعزول بعقود محددة، دون API لتنفيذ shell حر.
- منع عام دون روت غير مدعوم في هذه النسخة؛ لا نستخدم VpnService كمحرك الفايروول الأساسي.
- SELinux يبقى Enforcing. صلاحية روت لا تعني كشف HTTPS ولا فك تشفير بيانات مغلقة.
- درجة شذوذ ودرجة خطورة وثقة بيانات مستقلة؛ لا نسوّق درجة عددية باعتبارها احتمال إصابة.
- لا رفع لملفات المستخدم أو سجل اتصالاته إلى السحابة افتراضيًا.
- المستشعرات غير المتاحة تُعرض كغير مدعومة، ولا تتحول قيمها إلى أصفار وهمية.
